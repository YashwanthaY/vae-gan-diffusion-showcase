# DIAGNOSIS: Repetition and Stagnation in Generative Lab

**Date**: November 7, 2026  
**Investigator**: Antigravity Assistant  
**Problem**: Pressing "Generate All 3 Models" gives the same images again and again (same grid, or the same images repeated inside a grid).

---

## Suspect Investigation & Verdicts

### 1. Seed Suspect: **TRUE (CRITICAL ROOT CAUSE)**
- **Observed Behavior**: In `src/components/GenerativeLab.jsx`, the component initialized `seed` with default `42`. The `handleGenerate` callback passed `Number(seed)` directly to `generateStudio`. Clicking "Generate All 3 Models" never generated a new seed. The only way a new seed could be created was if the user noticed and manually clicked the small secondary shuffle button (`Shuffle`).
- **Space Backend**: In Space `app.py`, `torch.manual_seed(effective_seed)` was set with the fixed seed received. Since the seed was repeatedly `42`, the latent noise $z$ generated by `torch.randn` for VAE, WGAN, and DDPM was numerically identical on every run.
- **Model Collision**: In `app.py`, all three models received the identical seed: `sample_vae_16(seed=effective_seed)`, `sample_wgan_16(seed=effective_seed)`, `sample_ddpm_16(..., seed=effective_seed)`.

### 2. CACHED Mode Suspect: **TRUE (CRITICAL ROOT CAUSE)**
- **Observed Behavior**: Whenever live ZeroGPU requests timed out or were rate-limited, the system seamlessly fell back to `getCachedStudioResponse` in `src/services/gradioClient.js`.
- **Static Invariant Mapping**:
  ```javascript
  const seedNum = Number(seed);
  const seedKey = [42, 123, 256].includes(seedNum) ? seedNum : 42;
  const ddpmUrl = classGridMap[normalizedClass] || `/img/grids/ddpm_seed${seedKey}.png`;
  const vaeUrl = `/img/grids/vae_seed${seedKey}.png`;
  const wganUrl = `/img/grids/wgan_seed${seedKey}.png`;
  ```
  - For DDPM: `ddpmUrl` was strictly mapped to a single static file per class (e.g. `ddpm_class5_dog.png`) regardless of seed.
  - For VAE and WGAN: any seed other than `123` or `256` fell back to `42`.
  - Result: Every single fallback run loaded the identical static image file.

### 3. Caching Layers Suspect: **TRUE (CONTRIBUTING FACTOR)**
- **Browser/HTTP Cache**: Image asset fetches for fallback grids lacked cache-busting query strings (`?ts=...`). The browser and service worker served cached PNG blobs from memory/disk cache without re-evaluating.
- **Client Prediction Memo**: Gradio client calls and internal fetch operations lacked explicit `cache: 'no-store'` directives and request correlation IDs.

### 4. Top-Up & Tile Splitting Suspect: **TRUE (CRITICAL FOR IN-GRID REPETITION)**
- **Observed Behavior**: In `src/utils/tileAssembler.js` (`assemble16Tiles`):
  - When a primary source had fewer than 16 tiles (e.g., 4 tiles from a 2×2 grid), the loop attempted to extract from `fallbackPath`.
  - If `fallbackPath` was the same grid file, it either added nothing (because `tiles.includes(t)`) or if it fell back to repeat logic, it would replicate the same tiles across multiple grid slots.
  - There was no shuffle bag or deduplicated tile pool across available bank grids and seeds.

### 5. React State & Closures Suspect: **TRUE (CONTRIBUTING FACTOR)**
- `handleGenerate` closed over static `seed` state. Without an auto-randomize mechanism or a "Lock seed" toggle, subsequent button triggers executed with identical arguments.

---

## Action Plan for Fixes

1. **Fix A (Seeds & Lock Seed Toggle)**:
   - Add a "Lock seed" checkbox (default `false`) next to the seed input in `GenerativeLab.jsx`.
   - When Lock seed is `false`: Every press of "Generate" generates a fresh 31-bit random seed (`crypto.getRandomValues`), writes it to the input field, updates "Active sample: seed S", and passes it to the generation service.
   - When Lock seed is `true`: The current seed is preserved for reproducible benchmark comparison runs.
   - Distinct seeds per model: The 3 model panels use `seed`, `seed + 1`, and `seed + 2` to ensure they never share identical noise vectors.
   - Add "new batch #N · seed S" badge on each model grid card.
   - Add keyboard shortcut (`Enter` or `R`) to "Generate again" with fresh seed.

2. **Fix B (Space app.py & models.py Generator Isolation)**:
   - In `app.py`, utilize `torch.Generator(device=device).manual_seed(seed)` for:
     - `sample_vae_16`: `torch.randn(16, 128, generator=gen)`
     - `sample_wgan_16`: `torch.randn(32, 128, generator=gen)`
     - `sample_ddpm_16`: `torch.randn(16, 3, 32, 32, generator=gen)` in `models.py:ddim_sample`
   - Use `secrets.randbits(31)` if no seed is provided.
   - Ensure the 16 images in each batch come from 16 independent noise vectors.

3. **Fix C (Cache Busting)**:
   - Add unique request IDs (`req_id = ${seed}_${Date.now()}`) to all requests.
   - Add `cache: 'no-store'` to fetches and `Cache-Control: no-store` headers.

4. **Fix D (CACHED Mode Diverse Tile Pool & Shuffle Bag)**:
   - Build a comprehensive tile pool from all bundled bank grids across seeds and classes.
   - Implement a deterministic shuffle bag seeded by `seed` that draws 16 tiles **without replacement**.
   - Maintain a session-level Set of shown tile hashes (`SHA-1` / visual hash) to prefer unseen tiles across consecutive runs.
   - Guarantee zero duplicate tiles inside any 4×4 grid.

5. **Fix E & F (Evidence, Synthetic Data Builder & Verification)**:
   - Synthetic Data builder assigns independent seeds per batch (`base_seed + batch_index`) and draws without replacement.
   - Report `"0 duplicates"` verified via hash in `metadata.json`.
   - Comprehensive unit and Playwright integration tests verifying tile diversity and seed variance.
